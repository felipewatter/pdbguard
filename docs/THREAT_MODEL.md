# Threat model — PDBGuard

## Assets

Integrity of maintenance review reports; confidentiality of Kubernetes resource metadata; availability of the local CLI; integrity of the release and CI pipeline.

## Trust boundaries

1. `kubectl`-exported JSON is external input; parse strictly even if generated by an authorized operator.
2. Snapshot files may reveal infrastructure labels and workloads; the tool never uploads or connects to a cluster.
3. Local output files can be misdirected by path manipulation; explicit symlinks are rejected for output (race-free file-system transactions are not guaranteed).
4. GitHub workflows and release artifacts are external supply-chain components; Actions dependencies are pinned to immutable commit SHAs and the release requires a successful CI run for the candidate commit.

## Threats and mitigations

| Threat | Mitigation / caveat |
|---|---|
| Malformed or oversized input | Max 8 MiB input, maximum resource counts, types checked, unknown selector operators rejected, NaN and duplicated JSON object keys rejected |
| Misleading positive result | Advisory-only banner, `advisoryOnly: true`, conservative blockers and explicit unsupported scheduler/storage semantics |
| PDB ambiguity/staleness | Multiple matching PDBs blocked; observed generation older than spec generation blocked |
| PDB quota exhaustion | Real `disruptionsAllowed` budget counted for every healthy Pod in simultaneous wave |
| Local ephemeral data loss | Block on `emptyDir` without explicit acknowledgment |
| Unmanaged workload eviction | Block without explicit acknowledgment |
| Sensitive data exfiltration | No telemetry endpoint, secrets, kubeconfig support, HTTP clients or subprocess invocation |
| Deceptive labels | Strict selector logic; still cannot detect mislabeled/missing Kubernetes resources in snapshot |
| Build compromise | Limited build dependencies, pinned GitHub Actions, workflow permissions scoped and public release after successful CI |

## Out of scope

Kubernetes scheduler simulation; realtime admission/eviction; PersistentVolume behavior; node disk, CPU or memory capacity; quorum of applications; unmanaged controllers/operators; authorized `kubectl` execution; container runtime; multi-cluster; cryptographic signatures of snapshots. Reports are **not** proofs of safety.
